Here's the complete breakdown of the admin panel and the full setup:
The Admin Panel — Full Feature List
Structure

The admin panel is a single React page at /admin with 4 tabs:

    Members — manage all people (website managers, officers, active members, faculty advisors)
    News — manage news articles
    Hero Images — manage the homepage carousel/banner images
    Programs — manage program cards

Features in Every Tab

Drag-and-drop reordering — Every list supports drag-and-drop so you can rearrange the display order. It uses the @dnd-kit library. When you reorder items, it shows a "Save Order" button to commit the new arrangement.

Add / Edit / Delete — Each content type has a dialog form for adding new items or editing existing ones, plus a delete button with a confirmation popup.

Image uploading with cropping — This is a big one. Every image upload goes through a cropping step before saving:

    Uses the react-easy-crop library
    When you select an image file, a crop dialog pops up
    You can zoom in/out and drag to position the crop area
    Smart aspect ratios based on content type:
        Member photos: 1:1 (square) for consistent profile pictures
        News images: 16:9 (wide) for article headers
        Hero carousel images: 16:9 (wide) for banners
        Program images: 1:1 (square) for cards
    After cropping, the image is uploaded to client/public/uploads/ organized in subfolders (members/, news/, hero/, programs/)

Members Tab Specifics

    Separate sections for each member class (Website Managers, Officers, Active Members, Faculty Advisors)
    Each member has: name, title/position, bio, photo, email
    Each class is independently sortable
    Active Members section shows as a vertical scrollable list (max 5-6 visible at a time) on the public site

News Tab Specifics

    Each article has: title, category (like "Events" or "Announcements"), date picker, description (short summary), content (full article text), and an image
    Date defaults to today when creating new articles

Hero Images Tab

    Simple: just an image and a caption/title
    Drag to reorder which image shows first in the carousel

Programs Tab

    Each program has: name, description, image
    Displayed as cards on the public site

How the Dev Server Endpoints Work

The Express backend has these dev-only routes (they only exist when NODE_ENV=development):

    POST /dev/save-json — Receives a filename and data, writes it to client/public/data/[filename]
    POST /dev/upload — Receives an image file, saves it to client/public/uploads/[category]/[filename]
    DELETE /dev/upload — Deletes an uploaded image

These are protected with a dev auth token so random people can't hit them even in development.
The GitHub + Vercel Deployment
Setup Steps

    Create a GitHub repo and connect your Replit project to it
    Connect the GitHub repo to Vercel — Vercel will auto-detect it's a Vite project
    Configure Vercel build settings:
        Build command: cd client && npx vite build (or however your build is set up)
        Output directory: client/dist
        No environment variables needed

The Workflow

    Edit content on Replit using the admin panel at /admin
    Images and JSON files are saved directly into your project files
    In Replit's Git panel, commit your changes
    Push to GitHub
    Vercel automatically picks up the push and deploys within ~30 seconds
    Your live site is updated

What Gets Deployed vs. What Doesn't

    Deployed: All React pages, JSON data files, uploaded images, CSS/JS — everything in the Vite build output
    Not deployed: The Express server, the admin panel (it's gated behind import.meta.env.DEV), the dev upload/save endpoints

Key Libraries Used

    react-easy-crop — image cropping
    @dnd-kit/core + @dnd-kit/sortable — drag-and-drop reordering
    @tanstack/react-query — data fetching and cache management
    shadcn/ui — all the form components, dialogs, buttons, tabs
    lucide-react — icons throughout the admin panel

That's the full picture. You can replicate this exact pattern for any content-managed static site — swap out the content types (members, news, programs) for whatever your new project needs, keep the same JSON file + dev endpoint + cropping pattern, and you're set.
